# happybox-bot

Telegram-бот HappyBox: регистрация владельца профиля, генерация персональной
ссылки `my.happybox.uz/<username>` и (далее) кошелёк с подаренными сертификатами.

## Что делает сейчас

- `/start` → просит поделиться номером (кнопка «Поделиться номером») → спрашивает пол
  (М/Ж) → вызывает бэкенд и присылает готовую ссылку для Telegram-био.
- `/link` → показывает уже созданную ссылку.

Аккаунт рождается **здесь**: телефон + `chat_id` + пол. Приложение и веб входят в
тот же аккаунт по телефону (вход по OTP, код шлёт этот же бот).

## Архитектура

- **Бот (этот сервис)** — обрабатывает *входящие* апдейты (команды, регистрацию),
  ходит в бэкенд по внутреннему API (`/api/bot/*`) с заголовком `x-bot-secret`.
- **happybox_back** — владелец БД. *Отправляет* OTP-коды и пуши тем же ботом
  (через Telegram API), используя тот же `BOT_TOKEN`. Отправка — stateless HTTP,
  поэтому конфликта с long polling бота нет (входящие апдеты получает только бот).

## Запуск

```bash
cp .env.example .env   # заполнить BOT_TOKEN, BACKEND_URL, BOT_API_SECRET
npm install
npm run dev            # или npm start
```

`BOT_API_SECRET` должен совпадать с одноимённой переменной в `.env` бэкенда.

## Требуемые переменные на стороне happybox_back

```
TELEGRAM_BOT_TOKEN=<тот же токен, что BOT_TOKEN здесь>
BOT_API_SECRET=<тот же секрет>
MY_BASE_URL=https://my.happybox.uz
```
